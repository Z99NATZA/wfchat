# v0.3.6 - Structured Audit Logging And Interface Refinements

Release date: 2026-08-16

This patch release adds structured API logging that connects access and
security events by request id without exposing sensitive data. It also includes
the Web refinements completed since v0.3.5.

## Structured Observability

- Every API response emits one structured JSON `http_access` event with a
  server-generated request id, normalized route template, resolved source IP,
  status, outcome, duration, and available size metadata. The same request id
  is returned in `X-Request-ID` for correlation.
- Authentication lifecycle and profile updates emit bounded success or
  rejection events. Admin and Chat authorization failures, attachment, Cafe,
  and Voice security rejections, Memory authorization failures and resets, and
  Sync authorization failures and commits emit request-correlated audits.
- Event emission preserves existing response contracts. Unexpected server and
  database failures remain represented by HTTP access and existing error logs
  instead of producing misleading security outcomes.

## Privacy And Runtime Boundary

- Security and audit events use allowlisted fields and exclude credentials,
  request and response content, profile values, resource identifiers, provider
  and database details, and raw errors.
- The Rust API emits newline-delimited JSON to standard output in every
  environment. Docker captures the API container stream for `docker compose
  logs api`; the application does not write log files.
- The development/LAN Compose stack does not configure a logging driver,
  rotation, retention, external storage, or alerts. Production retention
  remains deployment-managed.

## Web And CI Refinements

- Chat image composition now includes a drag-and-drop surface and responsive
  gallery lightbox.
- The Cafe lobby and wardrobe use a more focused responsive layout, while the
  profile dialog, Chat sidebar, and companion-name localization are more
  consistent.
- Full-stack Chat and Cafe smoke coverage is more reliable across the Web, API,
  PostgreSQL, and WebSocket boundaries.
- Web runtime, build, and test dependencies are updated to versions that resolve
  the advisories known at release time.

## Upgrade Notes

- No database migration or new required environment key is introduced.
- Rebuild the API and Web to receive the complete release. Log consumers should
  parse each stdout line as an independent JSON event and use `request_id` for
  correlation.
