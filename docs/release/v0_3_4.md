# v0.3.4 - Production Chat Quotas And Friendly Limit Feedback

Release date: 2026-08-09

This patch release adds durable production chat-generation quotas and presents
chat, image, capacity, and provider failures as localized Aiko feedback.

## Daily Chat-Generation Quotas

- In production, registered accounts and Guest sessions can each receive up to
  50 successfully saved assistant replies per `Asia/Bangkok` calendar day.
  JSON and SSE sends use the same allowance; creating a chat does not consume
  it.
- A separate PostgreSQL-backed circuit breaker allows 2,000 provider-started
  chat generations per Bangkok day across all API instances. TTS,
  transcription, and automatic-memory provider work do not consume it.
- Owner and global capacity are reserved atomically. An unsuccessful turn
  releases the owner allowance; global use remains consumed after provider
  work starts, including later provider failure or client disconnect.
- Signing in carries the Guest session's usage into the account's daily total.
  Signing out does not grant a fresh allowance before the next daily reset.
- Interrupted requests are recovered safely; attempts that already reached the
  provider continue to count toward the global limit.

## Structured Limits And Friendly Feedback

- Existing HTTP statuses and public `error` text remain compatible. Enforced
  chat and image boundaries now add stable `reason` values, with matching
  `Retry-After` and `retry_after_seconds` metadata when a retry delay is known.
- The Web maps recognized limits, capacity contention, transport failures, and
  provider failures to localized Thai and English Aiko companion notices in
  the chat timeline. Recoverable failures use neutral feedback styling in both
  light and dark mode.
- Rejected sends retain the local user message and offer retry where safe.
  Transient notices and rejected local messages are not persisted, synced, or
  included in provider context.
- Image rejections retain specific guidance, while delete failures remain
  beside the sidebar action.
- An HTTP rejection received before SSE starts no longer falls back to the JSON
  send route, preventing one user action from being counted twice against the
  limits.

## Upgrade Notes

- The API applies the daily quota migration automatically at startup. Daily
  owner counters, the global counter, and retry-safe reservation state are
  stored in PostgreSQL, so daily quotas are shared across API instances and
  survive API restarts.
- `CHAT_REGISTERED_DAILY_QUOTA` and `CHAT_GUEST_DAILY_QUOTA` default to 50.
  `CHAT_GLOBAL_DAILY_GENERATION_LIMIT` defaults to 2,000. Production validation
  does not permit values above those defaults. Deployments using the defaults
  do not need to set these variables explicitly.
- Daily admission is disabled in development while the same chat send path and
  structured failure handling remain available.
- A new daily allowance begins at `00:00 Asia/Bangkok`. The Guest boundary
  remains best-effort because clearing browser state can create a new server
  session; the existing resolved-IP limits provide the temporary
  shared-network guard.
