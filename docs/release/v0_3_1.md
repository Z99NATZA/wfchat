# v0.3.1 - Cafe, Chat, And Production Security

Release date: 2026-08-03

This release expands Aiko Cafe, refines the responsive Cafe and Chat
experiences, and hardens production chat and session boundaries.

## Aiko Cafe

- Added Table Service and Cafe Rush to the activity rotation. Both activities
  use server-owned orders, claims, deliveries, timers, and rewards.
- Added ephemeral room chat with recent history, avatar speech bubbles,
  presence notices, unread state, and message rate and content limits.
- Added animated four-direction player sprites and the Cafe Apron reward while
  preserving visible player colors and equipped cosmetics.
- Improved mobile controls, HUD and overlay behavior, room-code copy feedback,
  collision alignment, and Cafe visual consistency.

## Chat And Application Experience

- Refined responsive Chat layouts, sidebars, composer controls, settings, and
  interaction states across desktop and mobile viewports.
- Simplified assistant-message presentation and fixed timeline behavior during
  streaming, layout changes, and short mobile conversations.
- Standardized compact side rails and shared application navigation across
  Chat, Cafe, Model2D, and PNGTuber pages.

## Security Changes

- Google login now replaces the guest session atomically, migrates supported
  account data, and revokes the previous session without exposing registered
  access through the old session id.
- Production accepts HTTPS DNS origins outside the closed local/reserved-name
  list and rejects single-label and IP-literal origins. Validation does not
  perform DNS resolution or public-suffix verification.
- Chat generation enforces request, context, output, timeout, rate, and
  concurrency limits at the backend.
- JSON and streaming chat share session, resolved-IP, and global rate limits.
  Upload, speech, and transcription use session and resolved-IP limits.
- Forwarded client IPs are trusted only from explicitly configured proxy CIDRs.
- Disabling image uploads removes attachment controls and rejects image-message
  requests at the backend.

This security work covers production Chat, authentication sessions, and their
directly related media endpoints. It is not a full-system security review.

## Reliability And Delivery

- Cafe collision geometry and the new activities remain server-authoritative,
  including recovery of unfinished work after a player disconnects.
- Mobile movement no longer stops when a stale direction-release event arrives
  after the player changes direction.
- CI now includes a Playwright full-stack smoke test that starts the API and Web
  app and verifies that a guest chat survives a browser reload.

## Upgrade Notes

- Database migrations are applied automatically at API startup. Existing chat
  and account data are retained.
- Review the production variables in `apps/api/.env.example`, especially
  `APP_ENV`, frontend origins, trusted-proxy CIDRs, chat safety limits, and media
  feature flags.
- `TRUST_PROXY_HEADERS=true` requires `TRUSTED_PROXY_CIDRS`.
- TLS termination and reverse-proxy infrastructure are not configured by this
  release.

[Mobile viewport](../mobile-viewport.md), and [Continuous integration](../ci.md)

## Compatibility And Boundaries

- Development and private-LAN defaults remain available.
- Existing attachment-limit behavior is unchanged.
- Rate and concurrency limits are maintained per API process and reset when the
  process restarts.
- Cafe room chat remains in memory, is not added to account memory, and ends
  with the room. Active Cafe rooms still do not survive an API restart or span
  multiple API processes.
